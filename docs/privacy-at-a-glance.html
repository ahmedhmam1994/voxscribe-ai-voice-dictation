What the Android button can see

Android only lets an app type into other apps through an accessibility service, so VoxScribe needs one. Here is all it does with it:

  • It notices which text box is focused and whether the keyboard is open, so the button shows only when it is useful.
  • It types your words into that one box, and reads that box's text only to add to it or to take back your last dictation.
  • It hides itself in password and PIN boxes and types nothing there.
  • It reads the name of the app you are in, only for per-app settings.
  • If you turn on "send it", it looks for a button named Send when you say it. It reads button names only, never your messages.
  • It does nothing at all unless you hold or tap the button.

It never reads the rest of your screen, never sees what you type with your keyboard, and stores or sends none of it.

Password boxes on Windows

Before typing, the Windows app asks Windows whether the focused box is a password box, through the same accessibility interface screen readers use. If it is, nothing is typed, and what you said is kept out of the transcript and the history. It only asks about the one focused box and stores nothing.

Files you transcribe

Audio and video files you import, on Windows or Android, are read and transcribed on your device. Only the files you pick are opened, and the text or captions are saved where you choose (or next to the originals for a folder). Nothing is uploaded.

Check it yourself

  • The code is open. Both apps are MIT licensed and the full source is on GitHub.
  • Windows connection log. Settings shows every outside connection VoxScribe has tried. Offline mode (Pro) blocks them all.
  • Airplane mode. Turn the network off and dictate. Both apps keep working once the model is on your device.
